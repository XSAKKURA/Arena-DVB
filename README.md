# Gladiator-DVB

Автономный агент для игровой платформы [Igra Station Arena](https://arena.roomcomm.xyz),
открывающей внешним программным агентам 21 игру через REST API.

Агент самостоятельно регистрирует ключ, открывает и занимает игровые столы, играет партии
и ведёт журнал результатов без участия оператора. Для каждой из 21 игры реализована
отдельная стратегия. Работа не прерывается перезапуском процесса.

Реализация не имеет внешних зависимостей: Python 3.10 и стандартная библиотека.

---

## 1. Установка и запуск

```bash
git clone https://github.com/XSAKKURA/Gladiator-DVB
cd Gladiator-DVB
python3 -m arena_agent run
```

При первом запуске агент регистрирует ключ через `POST /api/keys` и сохраняет его в
`~/.arena-dvb/key.json` с правами `0600`. Дополнительная настройка не требуется.

### 1.1. Команды

| Команда | Назначение |
|---|---|
| `run` | Непрерывная работа: обе линии, все доступные игры. Режим по умолчанию. |
| `once` | Выполнить ходы, ожидающие в заочных партиях, и завершиться. |
| `status` | Рейтинг, квоты, занятые столы. |
| `journal` | Последние завершённые партии со ссылками на страницы матчей. |
| `games` | Перечень игр с указанием наличия стратегии. |
| `register` | Получить ключ без начала игры. |

### 1.2. Параметры

| Параметр | Действие |
|---|---|
| `--games СПИСОК` | Ограничить обе линии перечисленными играми. |
| `--live-games СПИСОК` | Ограничить только живую линию; заочные партии продолжаются. |
| `--rated-only` | Исключить игры, не влияющие на рейтинг. |
| `--no-live` / `--no-async` | Отключить соответствующую линию. |
| `--async-tables N` | Число одновременных заочных столов, не более 8. |
| `--think СЕК` | Лимит времени на выбор одного живого хода. |
| `--no-chat` | Не отправлять сообщения в чат стола. |
| `-v` / `-q` | Уровень журналирования. |

## 2. Архитектура

### 2.1. Обоснование

Платформа накладывает два ограничения, определяющих структуру агента:

1. **Один ключ — один живой стол.** Живая партия требует присутствия; агент, занявший
   несколько живых столов, проигрывает часть из них по времени.
2. **До восьми заочных столов одновременно.** Стол в режиме `pace:"async"` предоставляет
   до 24 часов на ход, не требует непрерывного соединения и сохраняется при перезапуске
   платформы.

Из этого следует разделение на две линии, использующие один ключ:

| Линия | Столов | Игр | Свойства |
|---|---|---|---|
| Заочная | до 7 | 8 (с признаком `async`) | Сохраняются между перезапусками, требуют малого числа обращений к API. |
| Живая | 1 | все 21, по циклу | Обеспечивают участие в играх, не поддерживающих заочный режим. |

Обе линии исполняются в одном кооперативном потоке. Дедлайн живого хода составляет
15 минут между агентами, что многократно превышает задержку от обслуживания второй линии.
Однопоточность исключает блокировки на пути к отправке хода.

### 2.2. Выбор стола

Живая линия отбирает игру по критерию наибольшей давности участия, что обеспечивает
равномерное распределение партий между играми. Присоединение к уже открытому столу
предпочитается открытию собственного: партия начинается немедленно, тогда как собственный
стол требует ожидания и при незаполнении расходует суточную квоту столов впустую.

Проверялась гипотеза о том, что открытие стола даёт право первого хода. На выборке из
21 партии первым ходил открывший стол в 52 % случаев и присоединившийся — в 48 %, что не
отличимо от случайного назначения. Преимущество первого хода в ряде игр существенно
(гомоку, артиллерия), однако способом получения стола оно не управляется, поэтому
приоритет присоединения сохранён как решение, оптимизирующее число сыгранных партий.
Способ получения стола и очерёдность хода записываются в журнал, что позволяет
перепроверить вывод на большей выборке.

Когда открытых столов несколько, выбирается тот, где произведение доли наших побед в
этой игре на долю поражений соперника в ней же максимально. Обе величины берутся из
открытых данных: наша — из собственного журнала, соперника — со страницы `/a/{имя}`,
публикацию которой платформа предусматривает именно для подготовки. При недостатке
наблюдений (менее трёх партий) используется нейтральная оценка 0.5, поэтому соперник
без истории не считается ни лёгким, ни опасным.

### 2.3. Состав

```
arena_agent/
├── client.py    REST-транспорт: квоты, повторы, обработка 429
├── runner.py    линии, жизненный цикл столов, восстановление состояния
├── match.py     ведение отдельной партии
├── store.py     ключ, журнал, статистика, модели соперников, выученные константы
├── chat.py      обмен сообщениями через roomcomm
├── scout.py     изучение соперников по их публичным партиям
├── brains/      стратегии, по одной на игру
└── engines/     движки шахмат и шашек, мост к UCI
tests/           53 автономных теста
```

Интерфейс стратегии состоит из одного метода: по состоянию партии вернуть ход либо `None`.
Возврат `None` означает «ход сейчас не требуется» и обеспечивает поддержку одновременных
игр, в которых поле `yourTurn` отсутствует, а факт отправки определяется флагом `picked`
или `submitted`.

Добавление игры требует одного файла: наследование от `Brain`, задание атрибута `game`,
реализация `choose` и регистрация декоратором `@register`.

## 3. Учёт ресурсных ограничений

Бесплатный тариф платформы предоставляет в сутки: 3000 ходов, 60 столов, 1500 «пустых»
чтений (обращений, не вернувших событий). Измерение показало, что ограничивающими
являются чтения и столы, но не ходы.

Применяются следующие меры:

1. **Заочная линия обслуживается одним запросом.** `GET /api/my/turns` возвращает перечень
   столов, ожидающих хода, для всех партий сразу. Раздельный опрос семи столов с интервалом
   150 с потребовал бы около 4000 чтений в сутки, что превышает квоту.
2. **Ожидание соперника не расходует квоту чтений.** Пока стол не заполнен, опрашивается
   `GET /api/tables`; платформа не тарифицирует это обращение как пустое чтение и
   одновременно считает его подтверждением активности.
3. **Адаптивный интервал опроса живой партии.** От 2 с после события до 60 с при
   отсутствии изменений. Верхняя граница выбрана из условия многократного запаса
   относительно дедлайна хода в 15 минут.
4. **Расход считывается с платформы, а не подсчитывается локально.** Локальный счётчик
   обнуляется при перезапуске процесса, тогда как квота платформы — календарная.
   Значение `spent_today` запрашивается при запуске и синхронизируется каждые 10 минут.
5. **Открытие столов ограничено темпом.** За заочной линией резервируется часть суточной
   квоты столов; живая линия распределяет остаток на время до обнуления квоты в полночь UTC.

Ответ `429` приостанавливает весь исходящий трафик на указанное в `Retry-After` время,
поскольку квота относится к ключу, а не к отдельному методу.

## 4. Устойчивость

**Восстановление состояния.** При запуске выполняется запрос `GET /api/keys/me` и
`GET /api/my/turns`; агент возвращается к занятым столам вместо открытия новых. Заочные
партии восстанавливаются с сохранением позиции, цветов и показаний часов. Живая партия
перезапуск платформы не переживает, о чём платформа сообщает в тексте ошибки.

**Отказ стратегии.** Исключение в модуле стратегии ранее приводило к отсутствию хода и,
как следствие, к поражению по времени. В играх, публикующих список допустимых ходов
(шахматы, шашки, реверси), выполняется ход из этого списка. В остальных играх ход не
отправляется: отклонённый ход не останавливает отсчёт времени, поэтому корректным
результатом является запись в журнал.

**Завершение работы.** Заочные столы не освобождаются: они рассчитаны на возобновление
тем же ключом. Живой стол может быть освобождён по явному указанию.

## 5. Методы по играм

Отметка ✅ означает, что платформа публикует список допустимых ходов и задача сводится к
выбору из него.

| Игра | Метод |
|---|---|
| `chess` ✅ | Альфа-бета с итеративным углублением, форсированным поиском, упорядочиванием MVV-LVA, killer- и history-эвристиками, нулевым ходом, сокращением поздних ходов и таблицей транспозиций на хешах Zobrist. При наличии в системе UCI-движка используется он. |
| `checkers` ✅ | Альфа-бета с продлением на взятиях и таблицей транспозиций. Реализованы правила русских шашек: взятие назад простыми, дальнобойные дамки, обязательность и свобода выбора взятия, превращение в середине цепочки. |
| `reversi` ✅ | Оценка по углам, подвижности и числу фронтовых фишек; точный досчёт при 12 и менее пустых полях. |
| `gomoku` | Проверка форсированных продолжений с последующей альфа-бетой по шаблонным оценкам; перебор ограничен окрестностью занятых клеток. |
| `bulls` | Полный перебор 5040 кандидатов с отсевом по каждому ответу; выбор догадки по минимаксному критерию Кнута. |
| `seabattle` | Прицеливание по плотности вероятности расположения уцелевших кораблей; правило запрета касания используется для исключения клеток вокруг потопленных. Расстановка смещается в клетки наименьшей плотности — те, что стрелок проверяет последними, — с вероятностным выбором среди образцов, чтобы расстановка не стала читаемой. |
| `tanks` | Байесовская сетка положения противника; сброс при обнаружении, диффузия на один шаг за ход. Выстрел выполняется каждый ход, поскольку не раскрывает сведений сверх оставляемого следа. |
| `dotsboxes` | Анализ цепочек и их чётности; точный досчёт при 16 и менее свободных рёбрах. |
| `karateka` | Воспроизведение частотной таблицы, ведущейся станционным ботом, и выбор хода, побеждающего предсказанный контрход. |
| `artillery` | Определение констант баллистики по вторым разностям наблюдаемой траектории; прицеливание численным моделированием по рельефу. Константы сохраняются между партиями. |
| `rule` | Преобразование правил открытого списка в предикаты, отсев несовместимых, выбор пробы по критерию равного разделения кандидатов. |
| `threefronts` | Апостериорная оценка распределения разбиений соперника; ответ софтмаксом по наилучшим ответам. |
| `pact` | Сотрудничество с однократным возмездием и прощением; отклонение в последнем раунде, поскольку взаимное сотрудничество даёт ничью. |
| `rps`, `rpsls` | Равномерное распределение (равновесие Нэша) с отклонением в сторону контрхода при статистически заметном смещении соперника. |
| `durak` | Отбой минимальной достаточной картой; отказ от размена козырей при непустой колоде. |
| `president` | Сброс младшего ранга полным набором; ответ минимальным допустимым набором без разбиения групп. |
| `believe` | Учёт заявок относительно четырёх экземпляров каждого ранга; обязательное сомнение при заявке последних карт. |
| `mind` | Задержка, пропорциональная математическому ожиданию числа карт партнёра ниже собственной младшей. |
| `onewave` | Выбор прототипического представителя категории; при отсутствии выраженного — первый элемент общего списка. |
| `fifteen` | Взвешенный A* по манхэттенскому расстоянию с поправкой на линейные конфликты. |

## 7. Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ARENA_KEY` | — | Ключ, имеющий приоритет над сохранённым в файле. |
| `ARENA_STATE_DIR` | `~/.arena-dvb` | Каталог состояния: ключ, журнал, статистика, выученные константы. |
| `ARENA_AGENT_NAME` | `DVB-Arena` | Имя для регистрации. |
| `ARENA_OWNER` | `xsakkura` | Владелец агента. |
| `ARENA_RUNTIME`, `ARENA_MODEL` | `Claude Code`, `Opus 5` | Самоописание, передаваемое платформе. |
| `ARENA_UCI_ENGINE` | — | Путь к UCI-движку. |
| `ARENA_LOG_LEVEL` | `INFO` | Уровень журналирования. |

Ключ возвращается платформой однократно и хранится в виде хеша SHA-256; восстановление
невозможно. С ключом связаны рейтинг и зарезервированное имя, поэтому файл
`$ARENA_STATE_DIR/key.json` подлежит резервному копированию. Каталог состояния исключён
из системы контроля версий.

## 8. Развёртывание

### 8.1. Периодический запуск

Режим `once` предназначен для сред, не допускающих непрерывной работы. Он пополняет
заочные столы, выполняет ожидающие ходы и завершается.

```cron
*/30 * * * * cd /opt/Gladiator-DVB && python3 -m arena_agent once >> arena.log 2>&1
```

### 8.2. Служба systemd

```ini
[Unit]
Description=Gladiator-DVB agent
After=network-online.target

[Service]
ExecStart=/usr/bin/python3 -m arena_agent run
WorkingDirectory=/opt/Gladiator-DVB
Environment=ARENA_STATE_DIR=/var/lib/arena-dvb
Restart=always
RestartSec=30

[Install]
WantedBy=multi-user.target
```

## 9. Ограничения

1. **Сила шахматной игры ограничена реализацией на Python.** При лимите 5 с встроенный
   поиск достигает глубины 6–7 полуходов (около 30 тыс. узлов в секунду). Этого
   достаточно для игры против агентов сопоставимой реализации. Подключение внешнего
   UCI-движка через `ARENA_UCI_ENGINE` даёт существенно больший эффект, чем дальнейшее
   улучшение встроенного поиска.
2. **Игры `rps` и `rpsls` не допускают преимущества** против соперника, играющего
   равновесную стратегию. Математическое ожидание изменения рейтинга в них равно нулю.
3. **Разбор правил в игре `rule` основан на анализе текста.** Формулировка, не
   соответствующая известным шаблонам, исключает правило из числа проверяемых; такое
   правило не называется без необходимости.
4. **Карточные игры используют эвристики, а не поиск.** Ожидаемый результат в `durak`,
   `president` и `believe` ниже, чем в играх с полной информацией.
5. **Соблюдение анонимности участников-людей** обеспечивается платформой: имя человека не
   передаётся агенту. Агент не сохраняет и не публикует сведений о соперниках-людях.

## 10. Взаимодействие с соперниками

Партиям между агентами платформа выделяет комнату чата. Агент отправляет приветствие при
занятии места и описание применённого метода по завершении партии. Сообщения формируются
на английском языке в соответствии с языком платформы. Ошибки при отправке подавляются:
сбой обмена сообщениями не должен влиять на ход партии.

Для повышения суточного лимита с 30 сообщений на IP-адрес до 500 при первом обращении
запрашивается ключ `roomcomm`.
